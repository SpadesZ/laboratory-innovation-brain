# ADR-0009: Two-tier error disclosure with an ACL-gated technical tier

Status: Accepted
Date: 2026-09-12
Affected Requirements: UX-002, UX-003, UX-006, SEC-001, SEC-002
Human Approval Required: Yes — P0 security semantics (granted via SAI 3.3 §17.23, §17.24)

## Context

Two failure modes pull in opposite directions. Show users a stack trace and NDA filenames,
private repository paths, restricted prompt fragments and query text leak past SEC-001 —
through a UI toggle nobody classified as an egress path. Show users nothing and the system
becomes unsupportable, which trains them to ignore every message it produces.

A third, subtler failure: rendering "the extractor was not confident" with failure styling
teaches users to click ACCEPT to clear it. That reintroduces hallucinated completion
(EVI-002) via the interface, after the backend correctly refused to guess.

## Constraints

- UX-002: five FROZEN `error_class` values; `POLICY_BLOCK` and `USER_INPUT_ERROR` MUST NOT be
  auto-retried; budget exhaustion classifies as `POLICY_BLOCK`, not `FAILED`.
- UX-003: technical diagnostics MUST NOT appear in the default payload. Expansion requires a
  server-side ACL scope check and MUST be redacted against the Actor's `sensitivity_clearance`
  while preserving `trace_id` / `job_id` / `span_id`. Cross-project `error_id` returns
  not-found, never permission-denied.
- UX-006: user-facing text comes from a versioned `MessageCatalog` keyed by `reason_code`, and
  MUST NOT be generated by an LLM at render time.

## Options Considered

1. **Single payload with full detail** — supportable, and a standing SEC-001 violation.
2. **Single redacted payload** — safe and unsupportable; `trace_id` alone cannot diagnose.
3. **Two tiers: catalog-backed user tier, ACL-gated + redacted technical tier.**

## Decision

Option 3.

The default payload carries `error_class`, `reason_code`, catalog text and
`remediation_actions[]` filtered by actor scope. `technical_detail_ref` is a *pointer*.
Expanding it is an authorization decision checked server-side against
`VIEW_TECHNICAL_DIAGNOSTICS`, then redacted against the requesting actor's clearance —
with `trace_id` / `job_id` / `span_id` preserved so the audit trail survives redaction.

`error_id` lookup is scoped by project membership. An `error_id` from another project returns
not-found, because permission-denied confirms the record exists.

User-visible text is never model-generated at render time. An LLM-written failure explanation
is an ungrounded inference presented as system fact, which is P3 / EVI-003 violated at the
presentation layer. An LLM MAY draft catalog entries offline, which are then reviewed and
versioned.

`EXTRACTION_WARNING` is rendered as a review item, never with failure styling.

## Consequences

- Positive: the disclosure boundary is one server-side check, not a per-field judgement
  scattered through a UI.
- Positive: identical wording for identical `reason_code` across CLI and any future web
  surface, because both read the same catalog.
- Negative: every new `reason_code` needs a catalog entry in every locale. Accepted — `GROWING`
  stability tier (§17.23) allows adding codes without an ADR, only a catalog entry.
- Negative: the CLI needs an authenticated actor context even to show an error detail. That is
  the cost of the boundary being real.
- `error_class` is FROZEN at five values. A sixth requires an ADR, because downstream retry
  and ownership logic branches on it.

## Migration / Rollback

`MessageCatalog` is versioned per locale (`configs/message_catalog/*.yaml`). Adding entries is
forward-compatible; an unknown `reason_code` fails closed to a generic catalog entry.

## Tests / Evidence

- `T-UX-002`: `POLICY_BLOCK` / `USER_INPUT_ERROR` fixtures produce zero retries; budget
  exhaustion classifies `POLICY_BLOCK`.
- `T-UX-003`: default payload has no stack trace, file path, repo name or prompt fragment;
  expansion without scope is denied; with scope but lower clearance returns redacted detail
  retaining `trace_id` / `job_id` / `span_id`; cross-project lookup returns not-found.
- `T-UX-006`: every emitted `reason_code` resolves in the catalog; no render path invokes a
  model slot.
