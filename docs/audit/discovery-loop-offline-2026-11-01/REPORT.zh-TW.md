## 1. 一句話結論

在同一批合成世界、同一組種子、同一個實驗預算下,
B2(LIB + Discovery)的正確結果率是 0.89,B1 是 0.31,B0 是 0.08。
B2 的錯誤發現率是 0.01,B1 是 0.25,B0 是 0.37。
但 B2 花的預算約是 B1 的 4 倍,「每個正確結果的成本」比 B1 差。
這是工程證據。不是科學驗證。不是獨立盲測。

## 2. 做了什麼

- **引擎** `src/lab_brain/discovery/`:不依賴任何領域。不匯入 DomainPack。不寫資料庫。
- **可區分的機制**:兩個假說只有在「某個可用實驗能把預測分開到雜訊之外」時,才算不同。
  - 統計量:兩個前向模型在各自參數範圍內最接近時,標準化距離是多少(最壞情況)。
  - 全部可用實驗各重複 4 次,距離仍小於 5:就是「不可區分」。
  - 不可區分的假說合成一個類別。只算一次。理由寫明:「沒有可用實驗能分開它們」。
  - 換名字的重複機制(前向模型相同)直接合併,不重複測試。
- **未解釋的觀測**:所有存活假說都解釋不了的觀測,會變成 `UNEXPLAINED` 異常紀錄。
  紀錄永不刪除。只能用事先登記的重測,判定為雜訊。
- **重新框架(Reframing)**:所有假說都失敗,或異常一直存在時,寫一筆只能新增的紀錄。
  種類:`QUESTION_THE_MEASUREMENT_CHAIN`、`WIDEN_MECHANISM_SPACE`、`NARROW_SCOPE`、
  `CHANGE_OBSERVABLE`、`STOP_INSUFFICIENT`。紀錄引用失敗的假說和異常。失敗歷史不會被刪。
- **實驗選擇**:每單位成本的「預期成對區分度」。預算固定,絕不超支。
- **狀態**:`PROPOSED`、`UNDER_TEST`、`SURVIVING`、`REFUTED`、`INDISTINGUISHABLE`、`STOPPED`;
  異常有 `UNEXPLAINED`、`ACCOMMODATED`、`EXPLAINED`、`ATTRIBUTED_TO_NOISE`。
  **沒有 CONFIRMED。** 最好的結果是「存活,等待 Causal Warrant Gate」。
- **事前登記**:只有在假說登記「之後」取得的觀測,才能支持它。登記前的資料只能反駁它。
  引發調查的那筆觀測(症狀)既不能支持,也不能反駁任何假說。
- **矽光子情境** `src/lab_brain/domains/silicon_photonics/discovery_catalog.py`:
  微環共振飄移與額外損耗。12 個實驗(1 個不可用:橢偏儀)、16 個機制類別、8 種世界。
  數值是玩具數字,只有正負號和趨勢有意義。用摘要值鎖定。沒有裝進產品。

## 3. 與 Causal Warrant Gate 的交接

- 這個 Gate 是唯一能產生 CONFIRMED 的路徑。離線時無法呼叫(需要資料庫、證據、簽章)。
- 所以 Discovery Loop 只交出一個型別化的封包(`GateHandover`),狀態永遠是
  `PENDING_CAUSAL_WARRANT_GATE`:
  - 候選類別、對手與它們的狀態、每個對手最能區分的實驗;
  - 每個成員「登記後」通過的觀測;
  - 從未考慮過的已宣告機制(封閉世界的殘餘風險);
  - 未解決的異常、可以拆開類別但不可用的實驗;
  - Gate 還要做的事:§8 收錄、綁定 OutcomeSpace、新的前瞻證據、DOMAIN 或簽章 REVIEW 授權、確認規則。
- `draft_certificates` 會產生未收錄的核心 `Hypothesis` 憑證。不產生 `Prediction`
  (需要 DomainPack 宣告的 OutcomeSpace,這裡沒有,也不能自己發明)。

## 4. 離線評估

### 4.1 設定

- 8 種世界,每種 25 個種子,共 200 個世界。評估種子 `2026110100`。
- 開發時只用開發種子 `1`。評估種子在協定凍結後(`c92e7df`)只跑一次。
- 預算:12 單位(另跑 8 和 16 做敏感度)。所有 arm 用同一個預算、同一批世界、同一組種子。
  同一個實驗的第 k 次執行,所有 arm 看到同一組雜訊(共同隨機數)。
- **B0「單一假說」**:先驗機率最高、又符合症狀的機制,只測一次,符合就接受。
  這是決定性的替身,**不是 LLM**。
- **B1「現有 LIB 風格」**:固定假說集合 + 驗證。沒有擴充、異常、重新框架、閉包。
  這是在同一個引擎裡重寫的「政策形狀」,**不是**真正的 PostgreSQL `VerificationLoop`。
- **B2「LIB + Discovery」**:全部功能開啟。
- 主要 arm 跑兩次。600 筆結果的摘要值完全相同。

- B2 − B1 正確率:+0.58 [0.515, 0.650]。B2 對 B1 錯:116 個世界;B1 對 B2 錯:0 個。

並且包含所有和真相一樣簡單、又分不開的替代。真相不在任何已宣告類別裡時,正確 = 不宣稱。

### 4.6 B2 沒有贏的地方(誠實列出)

- **效率**:B2 平均花 7.8 單位,B1 1.9,B0 1.1。每個正確結果的成本 B2(8.8)比 B1(6.2)差。
  原因:嚴格度(兩個不同實驗)、決定性重測、雜訊重測、對手閉包。
- **只有雜訊的世界**:B2 只有 11/25 正確。其餘 14 次預算用完、無法排除小幅度替代,停止。
  沒有錯誤發現,但也沒有答案。
- **兩個錯誤發現**:
  - `composition-01`:真相是 `fcd.static + nonlinear.tpa_fca`,B2 宣稱 `fcd.static`。
    第二個效應很弱,沒有產生異常,所以從未考慮組合。
  - `outside_initial_prior-21`:真相是小幅度的 `geometry.gap_large`,B2 宣稱「只有雜訊」。
    弱效應被當成沒有效應。
- **在初始目錄內的單一機制**:B1 也是 25/25。B2 在這裡沒有優勢,只是更貴。
- **多樣性**:B2 只比 B1 多 1.65 個可區分類別。它的優勢不在「看更多假說」。

## 5. 開發中先證明缺陷、再修正

詳見 `evidence/development-defects.md`。重點:

- 「數假說個數」的多樣性指標:加 50 個分不開的變體,從 3 變 53。類別數維持 3。測試先證明前者失敗。
- 「忽略登記時間」的支持規則:登記前的兩筆觀測就能讓假說算作「測過」。
  凍結的那次執行裡,這個規則會錯算 88 個假說。
- 開發種子上發現的引擎缺陷(都已修正):突波一次反駁所有對手後直接宣稱;
  只剩一個假說時從不測試未登記的已宣告對手;雜訊模型和小幅度替代永遠分不出來;
  閉包加入太多「成員 + 極小第二效應」;重測規則把 7σ 突波誤判為「已重現」。

## 6. 工程有效 vs 科學有效

- **工程有效**:演算法照設計運作。可重現。預算不超支。不產生 CONFIRMED。
  不把登記前的資料當支持。不把分不開的機制算兩次。異常不會消失。
- **不是科學有效**:世界是玩具前向模型,和引擎出自同一位實作者。
  數值沒有校準。沒有真實元件、真實量測或模型參與。
- **不是獨立盲測**:評估種子雖然在凍結後才跑,但世界的種類和產生器在開發時就看得到。
  保留種子只能防止「對種子過擬合」,不能防止「對設計過擬合」。

## 7. 限制

1. 封閉世界往上移了一層:擴充只能從已宣告的類別和兩兩組合中挑。真正新的機制只能被報告為「未解釋」。
2. 前向模型對每個振幅是線性的。沒有交互作用、非線性區段、相關雜訊。
3. 重測規則沒有時間模型。非平穩的效應可能被誤判為雜訊(這次的「宣告外」世界沒有發生)。
4. 「最壞情況」的可區分性比較保守。類別可能比必要的大。
5. 弱的第二效應會被漏掉(只有單一機制失敗時才考慮組合)。
6. B2 比基準花更多預算。
7. Gate 沒有被呼叫。交接是封包,不是執行。
8. B1 是政策形狀的重寫,不是真正的 `VerificationLoop`;B0 不是 LLM。

## 8. 需要 Owner 決定的事

1. 是否把 Discovery Loop 接進研究流程(目前完全離線,沒有接)。接的話,交接封包要怎麼變成 Gate 的輸入。
2. 微環目錄是否成為產品領域知識。若是,需要程式碼審查、校準的數值、條件 schema 欄位(§23.4)。
3. 嚴格度與成本的取捨:目前要求兩個不同的前瞻實驗與一次決定性重測。這讓 B2 更貴。
4. 「只有雜訊」世界停止而不宣稱,是否可以接受;或是否要允許在預算用完時報告「無法排除的小效應」清單。
5. 是否需要一個真正的獨立盲測(不同作者寫世界、不同的前向模型)。
6. 是否讓擴充只用已宣告類別(現在的做法),或在將來接受人提出的新類別(需經審查)。
