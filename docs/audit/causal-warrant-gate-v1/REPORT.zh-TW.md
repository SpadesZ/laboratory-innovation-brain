## 1. 根因

【事實】`epi:7b56877f` 的錯誤確認，每一步都照規格執行：

1. 型別化預測與觀測完全吻合：`sp.normalization_basis = DISAGREES`。
2. 關聯判斷的類型，直接照抄預測作者宣告的效果（`verification/evidence.py`）。
   - 這個作者是模型，所以「SUPPORTS」等於模型自己宣稱「這個結果能診斷我的機制」。
   - 沒有任何人或領域知識認可過這個宣稱。
3. 轉移規則只檢查「有沒有 SUPPORTS」；權威、條件、獨立性都是觀測本身的性質，不是「觀測→機制」這條推論的性質。
4. 迴圈把「某個假說 SUPPORTED」直接當成「根因確認」，並把模型自由文字寫進失效類別。

【解讀】根因只有一句話：模型宣告的效果被當成證據。EPI-002 在 attestation 層禁止「模型陳述當證據」，
同一個陳述卻從上一層（關聯類型）回來了。

獨立驗證者（審查 1）九項主張全部無法推翻，並補充了以下事實：

| 補充 | 證據 |
|---|---|
| 同一缺陷造成的錯誤否決：`prj:bench-gemini` 的每一筆 CONTRADICTED 都是 Gemini 在 `sp.normalization_basis = AGREES` 上宣告的否證。被否決的都是「接觸電阻修正缺漏」這類機制，三次都只是剛好沒錯。否決對該 episode 是終局。 | `evidence/supports_history.out.txt` |
| 反向失效：`epi:d4c74098` 的真因把正確結果標成 PREDICTS，觀測到了也從未被確認。 | 前一任務紀錄 |
| 共享支持：兩個對手對同一結果都宣告 SUPPORTS 時，兩者都會升級，迴圈確認 id 排序在前的那個。正式環境的 id 是 UUID，等於隨機。 | 無模型重現 |
| 出處被洗掉：關聯只記錄研究者，沒有記錄真正宣告效果的模型推論。 | `rel:51f1fdc4` |

## 2. 污染調查（唯讀）

【事實】
- 整個部署只有一筆 CONFIRMED（`fan:30d9407f`，就是錯的那筆）。候選啟發式 0 筆、審查項目 0 筆。
- 後續 `epi:12265cfd` 的兩份驗證計畫把它記為 precedent。原因是症狀預設為研究目標，三次基準研究的問題相同。
- precedent 不影響決策、不顯示、不進入模型脈絡。後續 episode 的證據只來自原始報告。

【解讀】沒有決策或模型輸入被污染。歸納器（`MIN_SUPPORT = 2`）只差一次重現就會產生錯誤的候選啟發式。

證據：`evidence/contamination.*`、`evidence/report_reuse.*`、`evidence/bundle_sources.*`。

## 3. 架構決策

| 方案 | 結論 |
|---|---|
| 只靠領域宣告 | 必要但不足：新機制會卡住 |
| 模型自己寫因果依據 | 否決：自我認證 |
| 只要求多條獨立證據 | 不足：兩次代理觀測都「吻合」 |
| 依作者身分送審 | 可偽造（作者只是 provider 名稱） |
| **依內容而非作者的依據（DOMAIN 或 REVIEW）＋區分規則＋隔離** | **採用** |

實作內容：

- **依據閘門**：新版政策（2.0.0）只在有「診斷依據」時，才計入 SUPPORTS 或 CONTRADICTS。依據有兩種：
  - 領域套件版本化的宣告：機制名稱完全一致，且該假說宣告了完整的「特徵結果＋所有否證結果」；
  - 專案成員對該關聯的審查認可。
  - 權威、條件、獨立性只看有依據的關聯；同一計算重複執行只算一條證據線。
  - 只有在「有了依據就會改變判決」時才送人審查。
- **確認規則**：只有一個機制類別有被認可的支持時才確認，並且：
  - 該類別本身沒有被認可的否證；
  - 預測同一觀測的對手，都已被受治理的政策以有依據的否證否決（粗模擬的「質疑」不算）；
  - 沒有可能推翻結論、但尚未被回答的問題（不論是否已排入審查佇列）；
  - 整個 episode 沒有觀測到「另一個宣告類別」的特徵結果（不論有沒有人預測過）；
  - 整個 episode 沒有觀測到「候選類別本身不可能產生」的結果（宣告中的否證結果）。
  - 候選所屬的類別，只能來自綁定，或審查者以 `--is-class` 明確說明「這個假說就是某宣告類別」；
    只認可關聯不算。確認後以類別的正式名稱記錄，並附上類別宣告。
- **審查**：新增 `DIAGNOSTIC_WARRANT` 審查與 `lab-brain review list|show|resolve|expire`。
  - 只有專案的在職人員能回答；跑該 episode 的人與假說作者不能回答；逾期不能回答。
  - `show` 會顯示領域對該結果的歸屬（「這是 X 類別的宣告特徵」）。
  - `expire` 依 OPS-002 既有的逾期流程關閉過期審查，下次執行會重新詢問。
  - 資料庫觸發器對所有寫入者強制以上規則，並要求每筆授權都是其審查的結案紀錄。
  - 關聯必須引用至少一筆 attestation，且只能描述自己這次觀測（不能借用其他觀測、觀測量或 episode）。
- **歷史與隔離**：舊版政策保留，只供重新推導、不可再用於新轉移。沒有依據的舊確認保留在紀錄中，
  但不再作為 precedent 或歸納來源。

## 8. 限制、未解風險與需要人決定的事項

限制與未解風險：
- **封閉世界是固有限制。** 沒被提出的機制無法排除；從未被測試的對手會列在結論中。
- **一個只宣告 PREDICTS、且其否證無法檢查的對手，會讓 episode 暫停。** 目前沒有「R 不會產生這個結果」的審查（V1.1 可加）。
- **領域宣告是被信任的知識。** 版本升級時必須保留舊版宣告。
- **反向失效未修正。** 標成 PREDICTS 的真因不會被升級；執行後重新標記是被禁止的。
- **規劃仍依模型宣告的效果挑選檢查。**
- **授權無法撤銷，CLI 身分是自報的 `--actor`。** 有資料庫存取權的人可以冒用任何成員回答（審查 8 已實證）。
- **沒有產品路徑建立審查佇列政策；逾期清掃也沒有排程**（`review expire` 可手動執行；所有審查類型原本就有此缺口）。
- **真正共存的多重原因無法下結論。** 兩個類別都 SUPPORTED 時 episode 暫停；身分陳述對兩個不同原因是錯的，審查者不可用它解除卡住。
- **直接寫入資料庫的 CONFIRMED 列**只檢查依據引用是否來自升級決策，不檢查確認規則；與冒用身分同屬「有資料庫存取權」的信任等級。
- **撤回對手的肯定不會解除阻擋**；只有讓對手成為 CONTRADICTED 的有依據否證才行。
- **觀測掃描未套用 §6.18 隔離清單**（迴圈的信念投影目前也未套用）；最壞情況是阻擋，不會造成確認。
- **單人專案無法授權**（跑 episode 的人不能回答）；**量測型否證目前無法排除對手**（唯一的否決政策需要模擬）。
- **模型推理的研究現在多數需要人審查。**

需要您決定：
1. 哪個角色可以回答依據審查、回答管道是否需要驗證身分。
2. 預設審查佇列政策。
3. 是否加入 DISCRIMINATION 審查。
4. 是否另外標註 `fan:30d9407f`。
5. 合併、部署，以及是否重跑受治理的 Gemini 案例（需外部呼叫費用）。
6. V2：讓模型看到宣告的類別名稱（需重新資格驗證）。
7. 是否加入「多重原因」結論，或受治理的「以共存原因結案」動作。
8. 是否排程逾期清掃，以及是否為 CONFIRMED 列建立專用寫入函式。
