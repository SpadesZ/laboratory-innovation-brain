Desktop PostgreSQL 17 on localhost:5433), each version on its own fresh database, same window.

The report handed over for this work said the V1.1 PostgreSQL suites had become about 15x slower
(a run of 85 gate tests on 2026-10-14 took 9462 s). Nothing below reproduces that. Its cause was
not established: it was not reproduced under matched conditions, and the measurements below show
no code-driven regression of that order.

4. What the re-deriving reuse check costs (scripts/verify_cost.py, 4669af1 code, local)
   15 CONFIRMED analyses of one symptom in one project (5 benchmark cases x 3 rounds):
     trusted_confirmations                 2.16 s   (144 ms per conclusion re-derived)
     similar_failures, the same symptom    2.22 s   -> 15 precedents
     similar_failures, another symptom     0.002 s  -> 0 (507770f: symptom matched first)
   Before 507770f, case memory re-derived every confirmation of the project at every planning
   step, whatever its symptom. Now it re-derives only the conclusions of the same symptom: the
   same set of precedents. A project with N confirmations of the SAME symptom still pays about
   N x 144 ms (local) per planning step; see the design record section 13 for the cache that
   would remove it and what its invalidation must cover. No cache was added: every read still
   re-derives.
