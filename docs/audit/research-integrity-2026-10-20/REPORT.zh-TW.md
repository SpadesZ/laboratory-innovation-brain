## 3. 研究完整性（P1）

### 3.1 F-01：研究問題的分級會保存（`012q`，`e0b57dc`）

原本的問題：研究問題的分級只存在開啟 episode 的請求裡；續跑時以預設的 INTERNAL 重建，可能用低於問題本身的分級推理，甚至經外部路由送出。

【事實】
- `research_runs.question_label`：每個新 run 都必須有，續跑原樣沿用，寫入後不能改；舊資料保留 NULL，不推測。
- 只能用提問者可讀的分級開啟 episode；續跑沿用已記錄的分級，拒絕不同的分級；012q 之前的 episode 只能在該次 run 宣告分級後續跑。
- 端到端測試：實驗室機密的問題搭配 INTERNAL 資料，在第一次與續跑時都不會送到只對 INTERNAL 開放的模型。
- 收件匣也用這個分級：分級從未記錄的問題，對任何人都只顯示數量。

### 3.2 F-02：關係判斷的作廢不可逆（`012r`，`722dff0`）

原本的問題：UPDATE 可以重新打開已撤回的關係；作廢時還會把 `actor_id`（閘門的職責分離檢查讀的欄位）改成作廢者。

【事實】
- `actor_id` 不能改；`invalidated_by_actor_id` 記錄撤回者，只寫一次。
- 已關閉的關係不能重開、改日期、改理由或改歸屬；關係不能刪除。
- 已儲存的決策快照在新欄位未設定時省略它，所以既有決策仍能逐位元重現。

## 4. 帳號系統（P2、P3）

### 4.1 模型

【事實】
- 兩種角色：ADMIN、MEMBER。三種狀態：PENDING、ACTIVE、SUSPENDED。
- 流程：註冊 → 寄出的連結確認電子郵件 → 管理員核准 → 登入。確認連結的 GET 只顯示表單，POST 才消耗（郵件掃描器不會誤觸）。
- 第一位管理員由維運者以 `lab-brain admin bootstrap-admin` 建立；指令印出一次性的設定密碼連結，系統不產生、也不顯示密碼。
- 密碼：scrypt（N=2^15, r=8, p=1），至少 12 字元；權杖以 `secrets` 產生，資料庫只存 SHA-256。
- Session：cookie 只放隨機權杖（HttpOnly、SameSite=Strict，可設 Secure）；2 小時未使用或登入 12 小時後失效；登出、停用、重設密碼都會結束 session。
- CSRF 權杖綁定該 session（未登入時綁定匿名 cookie）。
- 郵件預設關閉：未設定郵件時，註冊與重設密碼都停用（fail closed）。

### 4.2 伺服器端授權

【事實】
- 身分只來自 session cookie，每個請求都重新從資料庫讀取帳號。表單裡的 actor、角色、專案 id 都不採信。
- 每個請求都由一份「以此人身分」的工作台副本處理，所以既有的研究路由、匯出、檔案讀取、跨專案引用，全部套用同一套專案成員與分級檢查。
- 非成員對研究路由一律得到相同的 404。
- 管理員不是專案成員時，只能透過「監督」頁面閱讀；每次檢視都會記錄，並顯示給該專案成員看。證據摘錄仍依分級遮蔽。
- 管理員權限不能用來改研究紀錄：監督頁面只讀；SQL 層的不可改規則對管理員一樣適用。

### 4.3 資料庫層規則（`012u`）

【事實】以下對每個寫入者都成立，不只應用程式：
- 帳號只能以 PENDING 的 MEMBER 建立；唯一例外是「還沒有任何有效管理員時」由維運者建立的第一位管理員；
- 帳號 id、actor、電子郵件、建立時間不能改；核准只能由「非本人」的有效管理員做一次；
- 永遠保留至少一位有效管理員；
- 帳號、session、權杖不能刪除；被撤銷的 session 不能恢復或延長；權杖只能用一次；
- 帳號事件與管理員存取紀錄只能新增。
