# Discovery Loop 獨立隱藏世界評估協定(摘要)

完整英文版:[`discovery-independent-evaluation-protocol.md`](discovery-independent-evaluation-protocol.md)。

狀態:協定草案 v0.1,等待 Owner 核准。還沒有做過任何獨立評估。
目前所有結果都是工程證據。世界由引擎同一作者系譜寫的。
`READY_FOR_REAL_RESEARCH` 仍為 false。G0 仍為 NOT PASSED。
Discovery 仍然離線、隔離。沒有 migration。沒有接研究流程。沒有正式科學確認。
沒有 LLM、網路、模擬器或付費呼叫。

## 1. 要回答的問題

- 在作者沒看過的隱藏世界上(包括真機制不在目錄裡的世界),
  加上 Discovery 之後,是否更常找到真因、更少錯誤發現,而且是用「實際花掉的」實驗成本來算?
- 通過也只代表「在這些合成世界上」。不代表物理真實、真實文獻或真實模型(第 9 節)。

## 2. 角色與分離

- **世界作者(W)**:寫隱藏世界、封存。不可給引擎作者或操作者看。
- **引擎作者(E)**:凍結引擎、目錄、協定。不可看到任何隱藏世界或評分前的個案輸出。
- **評估者(V)**:凍結執行 manifest、盲跑所有 arm、操作實驗室服務、揭露與評分。
- W、E、V 必須是不同的人。
- 寫過或改過引擎、目錄或本工具的 AI agent 工作階段(或其延續)算是引擎作者。它不能當 W 或 V。
- 至少兩位世界作者。每人寫利益衝突聲明。

## 3. 先承諾,後揭露

1. Owner 核准協定(第 11 節的值全部固定)。
2. E 凍結引擎:commit SHA、每個引擎檔案的 SHA-256、目錄摘要值、各 arm 的協定摘要值、環境 manifest。
3. E 公開介面:實驗、欄位、雜訊 sigma、成本、已宣告機制、先驗、預算格點。
4. W 在 repo 外寫世界。用 `parse_hidden_worlds` 驗證。用 `seal`(每個世界 32 bytes 隨機 salt)封存。
   公開承諾值的 root。封存檔留在 W 手上。
5. V 凍結執行 manifest。之後才能跑。
6. 盲跑:每個 arm、每個個案、每個上限,各一次。
7. 揭露:`reveal` 重算每個承諾值。任何不符就拒絕評分。
8. V 用凍結的評分器評分。R 稽核。Owner 決定。

- 只有當機可以用同一個種子重跑一次。
- 其他任何重跑、凍結後的修改、評分前偷看個案輸出:這次執行作廢,這批世界也作廢(要重寫)。

## 4. 什麼封存、什麼公開

- 隱藏世界檔(`lab-brain/discovery-hidden-worlds@1`)。schema 在
  `benchmarks/discovery_independent/hidden-worlds.schema.json`。真正的驗證器是 `parse_hidden_worlds`。
- 每個世界的 `public.removed`(不能做的實驗與原因)是 arm 唯一看得到的個案文字。
- `hidden`:類別、種子、效應、雜訊。效應可以是目錄裡的類別,也可以是引擎沒有的「表格效應」。
- 非整數一律寫成十進位字串(承諾值用的 canonical JSON 拒絕 float)。
- 驗證會拒絕:格式錯誤;移除原因或 suite 名稱提到真相(類別 id、家族、機制、區段、效應 id、類別名、世界 id);
  標成 `held_out` 但引擎其實分不開的世界。檢查是字面比對,V 仍要人工讀每個移除原因。
- 引擎套件(`lab-brain/discovery-engine-cases@1`)只有介面、不透明的 case id、公開部分、承諾值與 root。
  沒有世界 id、作者順序或類別。載入器拒絕任何真相欄位。
- 正式執行時,實驗室是另一個行程。引擎讀不到封存檔。實驗室自己計算實際成本。
  離線工具的 `blind_laboratory` 只防意外洩漏,不是安全邊界。

## 5. 世界組成與「沒見過的機制」

| 類別 | 真相 | 正確結果 |
|---|---|---|
| `declared` | 一個目錄類別 | 真相的類別(指標規則) |
| `composition` | 兩個不同家族的目錄類別 | 真相的類別 |
| `null` | 沒有效應 | `NO_EFFECT_BEYOND_NOISE` |
| `held_out` | 目錄與先驗都沒有的家族;穩態;引擎所有假說都分得開 | **不宣稱** |
| `aliased_held_out` | 同上,但某個引擎假說分不開 | 另外計分 |
| `non_stationary` | 隨量測次數改變的效應 | **不宣稱** |

- held-out 家族:不在初始集、變體、擴充、組合或先驗裡的任何地方。
- W 用表格寫前向模型,不可以改名或縮放目錄類別。V 在封存時檢查可區分性。
- 沒見過的機制:
  - 正確 = 不宣稱(報告未解釋、停止、或重新框架但不宣稱)。另外記錄:有沒有留下可行動的紀錄。
  - 強行套用(force-fit)= 宣稱任何機制類別 = 錯誤發現。
  - 假的「沒有效應」(false null)= 錯誤發現。
  - aliased:宣稱分不開的替身 = surrogate,另外報告,不算進主要指標。
- 能說出目錄外機制的 arm(LLM)若說對了,算「開放世界正確」,另外報告。引擎 arm 這項必然是 0。

## 6. 實際成本比較

- 上限格點 4、6、8、10、12、16、20、24。每個 arm 在每個上限都跑每個個案。
- 上限是天花板,不是成本。
- **實際成本** = 實驗室服務真正執行的實驗成本總和,由服務計算。引擎回報必須相等。
  服務會拒絕超過上限的實驗。
- 每個上限、每個 arm:正確率、錯誤發現率(Wilson)、實際成本(平均+bootstrap、中位數、p90、最大值)、
  使用率、預算用完比例、每個正確結果的實際成本(比值 bootstrap)。
- 成本—發現曲線、曲線下面積(AUC,配對 bootstrap)、第一次答對的預算(BFC,超出格點為設限)。
- **同預算** = 同上限 **而且** 報告實際用量。效率比較一定和錯誤發現率一起看。

## 7. 三個 arm

| arm | 真正的定義 | 目前的決定性替身(只限離線) |
|---|---|---|
| A 單一前沿 LLM | 一個固定版本的模型,拿到相同資訊和 `measure` 工具 | **B0「單一假說」:不是 LLM** |
| B 真正的現有 LIB 流程 | PostgreSQL 版 `VerificationLoop`,由 harness 驅動 | **B1「現有 LIB 風格」:在本引擎裡重寫的政策形狀,不是 PostgreSQL LIB** |
| C LIB + Discovery | B 加上整合後的 Discovery | **B2:離線引擎全開,未接研究流程** |

- A 要跑之前:Owner 核准的模型(預設本機;雲端需要支出上限與單價宣告)、
  固定模型 id/版本/權重雜湊、解碼參數、提示詞與工具 schema 雜湊、答案 schema、開放世界評分規則。
- B 要跑之前:harness 把目錄轉成 LIB 假說、把讀值轉成 Runs/Attestations、
  每個個案一個新的已 migrate 資料庫、用現有預算閘門與實驗室計量執行上限、狀態對應到結果詞彙、
  和 A 相同的模型固定。還需要 OutcomeSpace 的 Owner 決定。
- 污染控制:arm 讀不到封存檔、證據目錄、先前輸出、網路。所有提示詞與工具呼叫都記錄並雜湊,評分器搜尋真相字串。
- 資訊暴露控制:所有 arm 拿到完全相同的資訊。

## 8. 指標與統計

- 主要:真因發現(正確結果)。共同主要(安全):錯誤發現率、held-out 強行套用率。
- 次要:可區分機制多樣性(不是假說數量)、可區分實驗效率、實際成本效率(AUC、BFC、每個正確結果的成本)。
- 必要:獨立可重現(同 SHA 重跑結果相同;第二位評估者獨立評分一致;第二位世界作者的方向一致)。
- 主要端點只有一個:C − B 的 AUC 配對差,95% 配對 bootstrap(多位作者時用 cluster bootstrap)。
- 安全端點:參考上限 12 的錯誤發現率差,非劣性邊界 δ = 0.02;held-out 強行套用率差。
- 次要:每個上限的精確 McNemar,Holm 校正;Bonferroni 加寬的區間。
- 固定樣本數。不中途偷看。不選擇性停止。建議至少 130 個主要個案,其中至少 30% 是 `held_out`。
- 停止規則:當機、超支嘗試或計量不符超過 2% 就停。修正後用新 SHA;若看過輸出,世界作廢。

**什麼結果會否證「Discovery 有幫助」**:
- 主要區間上界低於 +0.02;或
- C 的錯誤發現率比 B 高超過 δ;或
- C 的 held-out 強行套用率比 B 高;或
- 某位作者的世界上效果反轉。

只有主要下界大於 0、安全端點成立、可重現性成立時,才算「支持」。其他都是「不確定」。
若 C 只在實際成本是 B 好幾倍時才贏,就照實寫:多花實驗換來更多發現,不是效率。

## 9. 合成獨立測試通過後仍然沒有驗證的事

- 物理真實:前向模型是玩具表格,振幅線性、高斯雜訊、沒有校準。
- 真實文獻:目錄沒有和文獻比對;沒有 arm 讀論文。
- 真實模型:A 和真正的 B 還沒跑。
- 真實實驗:成本、可用性、失敗模式都是宣告的數字。
- Causal Warrant Gate:從未被呼叫。這裡什麼都不確認。
- 一般化:只有一個情境(微環飄移與損耗)。

## 11. Owner 要固定的值

bootstrap 種子與次數、A 的模型與固定方式、B 是否在真正 PostgreSQL LIB 上跑、
評估者、世界作者、審查者的人選。
